# 流向配置指南

本文说明如何在**表单编辑**与**可视化编辑**中维护数据资产流向，以及如何正确配置**多路径**与**多步骤**。

---

## 一、三层模型

| 层级 | 名称 | 含义 | 关系 |
|------|------|------|------|
| **Flow 流向** | 一条业务连线 | 固定 **一个源落点 → 一个目标落点** | 属于某数据资产 |
| **Path 路径** | 备选通道 | 同一源→目标下的多条实现方式（主备、不同通道） | 属于一条 Flow |
| **Step 步骤** | 执行动作 | 路径内**按顺序**执行的处理环节 | 属于一条 Path |

```text
数据资产
 └── Flow（源 → 目标，用途=同步/接入/…）
      ├── Path 1（如：主通道 cloud201→idc306）
      │    ├── Step 1 → 程序 A @ 主机 H1（跨区发送）
      │    └── Step 2 → 程序 B @ 主机 H2（跨区接收）
      └── Path 2（如：备通道 cloud202→idc307）
           └── Step 1 → …
```

**一键成图**读取 Flow / Path / Step 后，将主路径步骤展开为：**源 → 程序 → … → 目标**。

---

## 二、入口与切换

| 入口 | 路径 | 说明 |
|------|------|------|
| 流向列表 | 资产 → **管理流向** | 查看全部流向，新建、编辑、删除 |
| 表单编辑 | 列表 → **编辑** / **新建流向** | 表格化填写，适合精确录入 |
| 可视化编辑 | 列表 → **可视化编辑** / **可视化** | 画布拖线 + 侧栏，布局与成图一致 |
| 成图页跳转 | 成图连线详情 → **可视化编辑** / **表单** | 从图直接改对应流向 |

两种编辑模式**共用同一套数据**，随时可互相切换，保存后生效。

## 三、表单编辑

### 3.1 基本流程

1. 进入 **管理流向** → **新建流向**（或编辑已有流向）
2. 填写 **源落点**、**目标落点**（支持树形搜索筛选）
3. 选择 **用途**（接入 / 共享 / 同步 / 转发 / 辅助）、**状态**、是否 **主流向**
4. 在 **路径** 区域维护至少一条路径
5. 每条路径下配置 **步骤**（程序、主机、方法）
6. 点击 **保存**

### 3.2 路径操作

- **添加路径**：同一源→目标增加备选通道（如主备、不同跨区链路）
- **路径名称**：建议写清通道含义，如 `cloud201→idc306`
- **排序**：数值越小越靠前；成图默认取**第一条启用路径**的步骤画主链
- **启用**：停用后不参与成图主链（仍可在完整模式或详情中查看）

### 3.3 步骤操作

- **添加步骤**：路径内按 `seq` 顺序执行
- **程序/脚本**：必填，表示谁在处理数据
- **主机**：可选，覆盖程序默认部署主机；成图会显示 **部署于** 关系
- **方法**：如直推、跨区发送、跨区接收、订阅转发等

## 四、可视化编辑

### 4.1 画布操作

1. 进入 **可视化编辑**；已有流向的端点会自动出现在画布
2. 工具栏 **添加落点** 可把更多落点加入画布
3. 从落点 **右侧圆点** 拖线到另一落点 **左侧圆点** → 创建新流向（或选中已有流向）
4. 点击连线 → 右侧侧栏编辑属性、路径、步骤
5. **保存** 写入台账；**表单编辑** 可跳转同一流向的表单页

### 4.2 多路径（可视化）

- 侧栏 **路径** 区用 Tab 切换各路径
- **添加路径** / **删除当前** 管理备选通道
- 画布连线标签在有多路径时显示 `用途 · N路径`

### 4.3 与成图的一致性

可视化画布复用成图布局算法，展示 **源 → 程序 → 目标** 及部署关系；侧栏修改步骤后画布实时更新。

## 五、多路径：何时用、怎么配

### 5.1 适用场景

| 场景 | 建议 |
|------|------|
| 主备两条物理通道（不同发送/接收主机对） | **一条 Flow，两条 Path** |
| 同一通道内先发送再接收 | **一条 Path，两个 Step**（见下节） |
| 完全无关的源→目标 | **两条 Flow** |

### 5.2 示例：主备跨区（多路径）

**Flow**：二区主题 A → 三区主题 A（用途：同步，主流向：是）

| Path | 名称 | 步骤概要 |
|------|------|----------|
| Path 1 | cloud201→idc306 | Step1 跨区发送 @ cloud201；Step2 跨区接收 @ idc306 |
| Path 2 | cloud202→idc307 | Step1 跨区发送 @ cloud202；Step2 跨区接收 @ idc307 |

### 5.3 常见错误

❌ **错误**：把「跨区发送」和「跨区接收」拆成 **两条 Path**（无发送端的接收、无接收端的发送）

✅ **正确**：**一条 Path** 内两步：`CROSS_ZONE_SEND` → `CROSS_ZONE_RECV`

## 六、多步骤：顺序与跨区

### 6.1 顺序规则

- 步骤按 **seq** 从小到大执行
- 同一路径内多个步骤可共用或切换程序/主机
- 成图主链按**第一条启用路径**的步骤顺序插入程序节点

### 6.2 跨区标准配法（单路径两步骤）

| seq | 方法 | 程序 | 主机 | 说明 |
|-----|------|------|------|------|
| 1 | 跨区发送 | cross-zone-send | 发送区主机 | 数据离开源安全区 |
| 2 | 跨区接收 | cross-zone-recv | 接收区主机 | 数据进入目标安全区 |

目标落点应指向 **Kafka 主题 / 目录 / 接口** 等最终落点，而不是集群卡片本身。

### 6.3 示例：订单文件（多步骤单路径）

**Flow**：外部目录 → 内部目录（用途：接入）

| seq | 方法 | 说明 |
|-----|------|------|
| 1 | 通知+拉取 | 监听通知后拉取文件 |
| 2 | 直推 | 推送到内部目录 |

## 七、字段速查

### 用途（purpose）

| 值 | 含义 |
|----|------|
| INGEST | 接入 |
| SHARE | 共享/供给 |
| SYNC | 同步 |
| FORWARD | 转发 |
| AUX | 辅助流向（成图可开关「含辅助」） |

### 常用步骤方法（method）

| 值 | 含义 |
|----|------|
| DIRECT_PUSH | 直推 |
| CROSS_ZONE_SEND | 跨区发送（发送端） |
| CROSS_ZONE_RECV | 跨区接收（接收端） |
| KAFKA_SUBSCRIBE_FORWARD | 订阅 Kafka 转发 |
| NOTIFY_THEN_PULL | 通知+拉取 |
| NOTIFY_THEN_SHARED_READ | 通知+共享读取 |
| SFTP_PUSH | SFTP 推送 |

## 八、配置检查清单

保存前建议确认：

- [ ] 源、目标落点类型正确（主题、目录、主机等）
- [ ] 跨区场景：发送+接收在 **同一路径** 的连续步骤中
- [ ] 主备/双通道：使用 **多 Path**，而非拆成多个仅含一步的 Path
- [ ] 每条路径至少一个步骤，且步骤已选程序
- [ ] 主流向标记是否符合业务（成图简洁模式只突出主流向）
- [ ] 保存后在 **一键成图** 中核对链路是否与预期一致
